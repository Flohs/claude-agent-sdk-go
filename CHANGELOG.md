### Added

- `TaskStartedMessage.Ambient`, `TaskNotificationMessage.Ambient`, and `BackgroundTaskInfo.Ambient` fields (`*bool`), true for housekeeping tasks the CLI does not surface as user work (every `skip_transcript` task, plus auto-started live-update watchers) — hosts should exclude these from activity indicators. `BackgroundTasksChangedMessage`'s doc comment is updated to note the message now also fires when an entry's `Ambient` flag flips, not just on membership changes. Port of TypeScript SDK v0.3.247 (npm package's bundled `sdk.d.ts`, confirmed by diffing the npm tarballs for v0.3.246 → v0.3.247 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#636](https://github.com/Flohs/claude-agent-sdk-go/issues/636))
- `ModelUsage.CostBasis` field (`"list"`, `"managed"`, or `"unknown"`), reporting which price table the most recent request for that model was priced at — Claude Code's built-in list prices, the organization's managed-settings `modelPricing` rates/multiplier, or neither (a guess at the default model's rate). Overwritten per request like `CanonicalModel`, so a consumer that differences the cumulative `CostUSD` per turn gets that turn's basis. Empty until this process has priced a request for the model (e.g. right after `--resume`) and on CLIs that predate the field. Port of TypeScript SDK v0.3.246 (npm package's bundled `sdk.d.ts`, confirmed by diffing the npm tarballs for v0.3.242 → v0.3.246 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#630](https://github.com/Flohs/claude-agent-sdk-go/issues/630))
- `AssistantMessage.UserMessageUUID` and `StreamEvent.UserMessageUUID` fields, the client uuid of the user message that triggered the turn — stamped on the turn's first reply frame (`AssistantMessage`) or, with `--include-partial-messages`, its first non-ping stream event (`StreamEvent`) — so a consumer can bind a reply to the send it answers without waiting for the result. Empty on later frames of the turn, on synthetic/scheduled turns, on turns without a client uuid, and from older CLIs. `ResultMessage.UserMessageUUID` already existed; its doc comment is corrected, since as of this port the field is also populated on error result subtypes, not just success. `StreamEvent`'s sibling `ttft_ms` field remains unmodeled (pre-existing gap, unrelated to this change). Port of TypeScript SDK v0.3.246 (npm package's bundled `sdk.d.ts`, confirmed by diffing the npm tarballs for v0.3.242 → v0.3.246 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#631](https://github.com/Flohs/claude-agent-sdk-go/issues/631))
- `ToolPermissionContext.DefaultToNo`, a bool set when the terminal prompt for a `can_use_tool` ask must default to declining (no digit-shortcut auto-accept). Same-shape sibling of the existing `SuppressAlwaysAllowRule`/`MatchedAskRule` fields sourced from the same ask payload. Port of TypeScript SDK v0.3.242 (npm package's bundled `sdk.d.ts`, confirmed by diffing the npm tarballs for v0.3.241 → v0.3.245 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#626](https://github.com/Flohs/claude-agent-sdk-go/issues/626))

- `ResultMessage.QueuedTurnCount` (`*int`), the number of user sends still queued when the result was produced. Nil when the CLI omits the field; 0 is a meaningful value (nothing queued), distinct from absent. Port of TypeScript SDK v0.3.242 (npm package's bundled `sdk.d.ts`, confirmed by diffing the npm tarballs for v0.3.241 → v0.3.245 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#627](https://github.com/Flohs/claude-agent-sdk-go/issues/627))

- `MessageOriginSubkindProjectsRelay` (`"projects-relay"`) constant for `MessageOrigin.Subkind` on `MessageOriginKindTaskNotification` deliveries: a Claude Code Projects delivery that Anthropic servers composed for the project's coordinator session and addressed to one of its thread sessions (the thread's first message, or a relay carrying project messages), stamped from server-asserted provenance. `Subkind` itself stays a plain `string` field, so this was a discoverability gap, not a parse bug — an unrecognized value already round-tripped through JSON correctly, same category as [#583](https://github.com/Flohs/claude-agent-sdk-go/issues/583)'s `MessageOriginKindUnclassified`. Port of TypeScript SDK v0.3.239 (bundled `sdk.d.ts`, confirmed by diffing the npm package tarballs for v0.3.238 → v0.3.239 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#620](https://github.com/Flohs/claude-agent-sdk-go/issues/620))

- `TaskStartedMessage.IsBackgrounded` (`*bool`) and `TaskStartedMessage.SpawnDepth` (`*int`) fields, carried on the CLI's `system`/`task_started` message. `IsBackgrounded` reports whether the task was registered in the background (a resumed subagent always is) versus in the foreground with the spawning tool call blocking on it; a later move to the background arrives as a separate `task_updated` patch, not a change to this field. `SpawnDepth` is the nesting depth of a spawned subagent (`local_agent`) task (1 for a top-level spawn, N+1 inside a depth-N agent) and is unset for other task types. Port of TypeScript SDK v0.3.238 (bundled `sdk.d.ts`, confirmed by diffing the npm package tarballs for v0.3.237 → v0.3.238 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#616](https://github.com/Flohs/claude-agent-sdk-go/issues/616))

- `UserPromptExpansionHookOutput` typed struct (`AdditionalContext string`, `SuppressOriginalPrompt bool`) for `HookEventUserPromptExpansion` callbacks, with a `ToHookJSONOutput()` method nesting both fields under `hookSpecificOutput`, following the existing `StopHookOutput`/`WorktreeCreateHookOutput` convention. `SuppressOriginalPrompt`, when combined with a `"block"` decision, omits the original prompt from the block message shown to the user. Previously only reachable via the generic `HookJSONOutput` map. Port of TypeScript SDK v0.3.238 (bundled `sdk.d.ts`, confirmed by diffing the npm package tarballs for v0.3.237 → v0.3.238 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#617](https://github.com/Flohs/claude-agent-sdk-go/issues/617))
- `PostToolUseHookOutput.AdditionalContext` and `PostToolUseHookOutput.ClassifierContext` string fields. `ClassifierContext`, when non-empty, is a short host-asserted note about a tool call's result that the auto-mode permission classifier reads alongside that result (honored on synchronous hook responses only). `AdditionalContext` injects extra context for the model alongside the tool's result, matching the existing `StopHookOutput`/`SubagentStopHookOutput` field of the same name. Port of TypeScript SDK v0.3.236. ([#613](https://github.com/Flohs/claude-agent-sdk-go/issues/613))

Populates `AssistantMessage.Error`/`StopFailureHookInput.Error`. Port of TypeScript SDK v0.3.235 (bundled `sdk.d.ts`, confirmed by diffing the npm package tarballs for v0.3.234 → v0.3.235 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#611](https://github.com/Flohs/claude-agent-sdk-go/issues/611))
- `MessageOrigin.FromMode` field, the sending session's permission class ("bypass" for sessions that run tools without asking, "prompting" otherwise) as declared by the host that injects a `peer`-kind message on local stdin — lets the recipient deliver a same-class message immediately while a cross-class or undeclared sender is still held at a recipient that runs without asking; empty when the host doesn't declare it. Populated for `MessageOriginKindPeer` only. Plain `string` field, matching `MessageOrigin.Subkind`'s existing convention. Port of TypeScript SDK v0.3.234 (bundled sdk.d.ts, confirmed by diffing the npm package tarballs for v0.3.233 → v0.3.234 directly, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#603](https://github.com/Flohs/claude-agent-sdk-go/issues/603))
- `Options.ForwardSubagentText bool` field, sent as `"forwardSubagentText": true` in the `initialize` control request (omitted when false), asking the CLI to forward subagent text and thinking blocks as messages in the stream — not just `tool_use`/`tool_result` blocks. By default only `tool_use`/`tool_result` blocks from subagents (spawned via the Agent tool) are emitted as `AssistantMessage`/`UserMessage` values whose `ParentToolUseID` is the spawning Agent `tool_use` id — enough for a progress heartbeat; with this option set, the subagent's text and thinking blocks are forwarded the same way, so consumers can render the full nested transcript. Threaded through `claude.Query`, `WarmQuery`, and `Client` the same way `Options.Agents`/`PresetPrompt.ExcludeDynamicSections` already are. Port of Python SDK commit [c97420c](https://github.com/anthropics/claude-agent-sdk-python/commit/c97420cbd3ddf4085ef6ccab5323284ddcb12f39) ("Add forward_subagent_text option", anthropics/claude-agent-sdk-python#1206), matching the TypeScript SDK's existing forwardSubagentText. ([#601](https://github.com/Flohs/claude-agent-sdk-go/issues/601))
- `AssistantMessage.ContextUsage` (`*AssistantContextUsage`), a structured twin of the `/context` report carried on the synthetic assistant message that delivers the markdown table — `Model`, `TotalTokens`, `RawMaxTokens`, `Percentage`, optional `OverLimit` (`TokensOver`, `Kind` of `"hard_limit"`/`"compaction_window"`), `Categories` (`AssistantContextUsageCategory`: `Name`, `Tokens`, `Kind` of `"used"`/`"free"`/`"buffer"`/`"deferred"`), `MCPTools`, `MemoryFiles`, `Agents`, and optional `Skills`. Nil except on `/context` results from CLIs new enough to attach it; `Content` remains the canonical markdown fallback. Distinct from the pre-existing `Client.GetContextUsage`/`ContextUsage`, an unrelated on-demand control-request/response shape. Port of TypeScript SDK v0.3.232 (`SDKContextUsage`, confirmed from the npm package's bundled `sdk.d.ts`, since the TypeScript SDK's GitHub repository does not expose this file directly). ([#594](https://github.com/Flohs/claude-agent-sdk-go/issues/594))
- `MessageOriginKindUnclassified` (`"unclassified"`) constant for `MessageOrigin.Kind`, completing the `MessageOriginKind` enum against the Python SDK's `MessageOriginKind` literal union (8 of 9 kinds already had named Go constants; `unclassified` was the missing one). `MessageOrigin.Kind` is a plain `string` field, so this was a discoverability gap, not a parse bug — an unrecognized value already round-tripped through JSON correctly. Port of Python SDK commit [d48fa33](https://github.com/anthropics/claude-agent-sdk-python/commit/d48fa33) (anthropics/claude-agent-sdk-python#1199). ([#583](https://github.com/Flohs/claude-agent-sdk-go/issues/583))
- `AgentToolUsage.OutputTokensDetails` field (`ThinkingTokens *int`), carrying the thinking-token breakdown of `AgentToolCompletedOutput.Usage.OutputTokens` when the CLI provides it. Port of TypeScript SDK v0.3.228 (`Agent tool results (AgentOutput): usage.output_tokens_details is now carried through`). ([#585](https://github.com/Flohs/claude-agent-sdk-go/issues/585))
- `ConversationResetMessage` (`NewConversationID`, `UUID`, `SessionID`), parsed from the CLI's `conversation_reset` frame, emitted when the session's conversation is replaced without ending the connection (e.g. after `/clear`). In streaming input mode a single connection can carry many user turns; a reset clears history and zeroes the running totals on subsequent `ResultMessage`s (e.g. `TotalCostUSD`), so callers accumulating those totals should snapshot them when this message arrives. Previously unrecognized `conversation_reset` frames fell through `ParseMessage`'s forward-compatible default case and were silently dropped. Port of Python SDK commit [54dd3b4](https://github.com/anthropics/claude-agent-sdk-python/commit/54dd3b4) (anthropics/claude-agent-sdk-python#1196). ([#582](https://github.com/Flohs/claude-agent-sdk-go/issues/582))
- `BashToolOutput.BackgroundEndsWithFinalResponse *bool` field, set when a backgrounded command is owned by a synchronous subagent and is therefore terminated when that agent gives its final response; nil when the command survives the call that started it (main loop, async subagents). Port of TypeScript SDK v0.3.227. ([#576](https://github.com/Flohs/claude-agent-sdk-go/issues/576))
- `ProposeGoalInput` (`Condition string`, `AskUser bool`) and `ProposeGoalOutput` (`Condition string`, `AskUser bool`) typed structs for the `ProposeGoal` tool, accessible from `PreToolUseHookInput.ToolInput`/`PostToolUseHookInput.ToolResponse` when `ToolName` is `"ProposeGoal"`. Same shape of feature as the existing `ProposeSkillsInput`/`ProposeSkillsOutput`. Port of TypeScript SDK v0.3.227. ([#577](https://github.com/Flohs/claude-agent-sdk-go/issues/577))

## [2.3.0] - 2026-06-24

### Changed

- **Module path:** the Go module path is now `github.com/Flohs/claude-agent-sdk-go/v2` (was `github.com/Flohs/claude-agent-sdk-go`), as required by Go's [semantic import versioning](https://go.dev/ref/mod#major-version-suffixes) for major version 2 and above. ### Fixed

- Input starting with `"/ "` (slash followed by whitespace, e.g. `"/ add tests"`) is now escaped with a leading space before being sent to the CLI, so it is treated as a plain text prompt rather than a malformed slash command that the CLI silently discards. Port of TypeScript SDK v0.3.172. ([#364](https://github.com/Flohs/claude-agent-sdk-go/issues/364))
- `ReceiveResponse` no longer terminates the message stream when a background-agent `ResultMessage` arrives before the main-session result. Previously any `ResultMessage` caused the channel to close immediately, dropping the main turn's result if a concurrent background agent finished first. The fix checks `ResultMessage.Origin`: only an empty `Origin` (main session) ends the stream; non-empty origins (e.g. `"task_notification"`) are forwarded but do not close the channel.
